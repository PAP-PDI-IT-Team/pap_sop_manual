# Glossary

## Requests and ownership

### 1. JO - Job Order

The reported ITD term for a request for IT action. Whether it is officially synonymous with Job Delivery Order remains open.

### 2. JDO - Job Order Delivery

The form title recorded in the sample. Equivalence with JO remains open.

### 3. ITD - Information Technology Department

Developers and maintainer of systems, website infrastructure, hardware devices, internet and technological devices.


### 5. PM - Project Manager

PA reported work-assignment role. Decision authority remains unverified.

### 6. ASD

The team reported to evaluate changes and participate in production validation. Its full name and formal acceptance authority are not established in these records.

### 8. SOP - Standard Operating Procedure

Current discovery records are not approved SOPs.

### 9. Renorming

Changes to assessment standards or baselines used for evaluation and narrative outcomes.

### 10. Decommissioning

Retiring a feature or function.

### 11. Purging

Deleting specified data; authorization and execution requirements remain open.

## Development and validation

### 12. QA - Quality Assurance

The reported workflow includes manual staging checks by a QA member.

### 13. UAT - User Acceptance Testing

Named in the sample timetable, with its relationship to the reported huddle still unverified.

### 14. PR - Pull Request

A proposed branch change submitted for review and merge.

### 15. CI/CD - Continuous Integration and Continuous Delivery or Deployment

The actual pipeline checks and conditions have not been verified.

### 16. ADR - Architecture Decision Record

Records an architectural decision and its rationale.

### 17. Dev - Development

Used in the records for the development branch.

### 18. Stg - Staging

The environment reported for manual QA; it must not be treated as synonymous with preproduction.

### 19. Preprod - Preproduction

The environment reported for the generic ASD huddle sequence. System-specific applicability remains open.

### 20. Pre-release

The branch reported to collect selected changes before a PR to preprod.

### 21. Huddle

A reported demonstration and evaluation of changes with ASD; formal attendance and acceptance evidence remain open.

### 22. Cherry-pick

A Git operation that replays selected commits. The local practice described as “cherry-pick by lines” means manually copying/editing selected code lines; see [version-control practice](processes/version-control-practice.md#working-with-changes).

### 23. Regression testing

Checking whether changes disrupted existing behavior. A separate regression stage is not verified by the sample timetable alone.

### 24. Rollback

Returning to an earlier release or state after a problem; responsibility and procedure remain unverified.

## Information and documentation

### 25. PII - Personally Identifiable Information

Information that identifies or can identify an individual.

### 26. SLA - Service Level Agreement

An agreement about service expectations. No SLA is established by these discovery records.

### 27. TOC - Table of Contents

The centralized listing of document titles and subtitles.

### 28. DRY - Don’t Repeat Yourself

Maintain shared information in one owning location and link to it.

### 29. SoC - Separation of Concerns

Give each document a distinct purpose and keep information in its owning location.
