# Design System

The standard record of fonts, colors, and components for the PAP SOP Manual site. Pages reuse these tokens and classes so the site stays consistent and does not introduce unapproved designs.

- **Included:** fonts, colors, small components, and common components used across pages.
- **Excluded:** specialized, page-specific areas.
- **Related issue:** Design System #2

## Source files

| File | Role |
| --- | --- |
| `assets/styles/main.css` | Source of truth: Tailwind import, color tokens, theme mapping, and shared component styles |
| `assets/styles/output.css` | Generated by Tailwind v4.3.5 from `main.css`. Linked by pages. Not committed and never edited by hand |
| `docs/design-system.md` | This document. The single reference for the design system |

Pages link the generated stylesheet. From a page inside `pages/<name>/`, the path is `../../assets/styles/output.css`.

Build commands:

- `npm run css:build` compiles once and minifies.
- `npm run css:watch` rebuilds on every save.

## Rules

- External CSS only. No `<style>` tags and no `style=""` attributes.
- Use the color tokens. Do not hard-code colors.
- Use the shared component classes before writing new CSS.
- Navigation lives in the footer only. The header shows the site name.
- Every page uses the same header and footer.
- Page-only styles go in that page's own CSS file, not in `main.css`.

## Typography

Body font: `system-ui, -apple-system, sans-serif`.
Code font: `ui-monospace, SFMono-Regular, Menlo, Monaco, Consolas, monospace`.

| Style | Selector or class | Size | Weight | Spacing |
| --- | --- | --- | --- | --- |
| Heading 1 | `h1`, `.text-h1` | 36px (2.25rem) | Bold (700) | Bottom margin 1rem |
| Heading 2 | `h2`, `.text-h2` | 24px (1.5rem) | SemiBold (600) | Bottom margin 1.5rem |
| Heading 3 | `h3`, `.text-h3` | 18px (1.125rem) | Medium (500) | Bottom margin 0.5rem |
| Body | `p`, `.text-body` | 14px (0.875rem) | Regular (400) | Line height 1.6, muted text color |
| Muted small | `.text-muted-sm` | 12px (0.75rem) | Regular | 80% opacity, muted text color |
| Code | `.font-mono.text-xs` | 12px (0.75rem) | Regular | Raised background, padding 0.2rem 0.4rem, 4px radius |

Headings (`h1`, `h2`, `h3`, `.text-header`) use the foreground color with a line height of 1.2.

Tailwind resets headings to inherit their size and weight, then `main.css` sets the sizes above. Use the heading elements or the `.text-h1` to `.text-h3` classes. Do not size headings with Tailwind text utilities.

## Buttons

Base class: `.btn`. Inline flex, centered, 14px, SemiBold, padding 0.6rem 1.2rem, 1px transparent border, `--radius` corners, 0.15s transition.

### Roles

| Role | Class | Use |
| --- | --- | --- |
| Primary | `.btn-primary` | The main, most favored action. **Use only once per button group.** |
| Secondary | `.btn-secondary` | Optional alternative action. |
| Tertiary | `.btn-tertiary` | Conditional or niche-specific actions. |

### Styles

| Style | How to apply |
| --- | --- |
| Full background | Role class alone: `btn btn-primary` |
| Border | Add `btn-border`: `btn btn-primary btn-border` |
| Disabled | Add the `disabled` attribute, or the `btn-disabled` class |

### What each combination looks like

| Combination | Background | Text | Border |
| --- | --- | --- | --- |
| Primary, full | `--primary` | `--primary-foreground` | Transparent |
| Primary, border | Transparent | `--primary` | `--primary` |
| Secondary, full | `--secondary` | `--secondary-foreground` | `--border` |
| Secondary, border | Transparent | `--foreground` | `--border` |
| Tertiary, full | Transparent | `--foreground` | Transparent |
| Tertiary, border | Transparent | `--foreground` | `--border` |
| Disabled (any role) | `--muted` | `--muted-foreground` | Transparent, 60% opacity, `not-allowed` cursor |

A correct group has one primary and optionally a secondary, for example Save and Cancel.

## Link

Class: `.link-style`. Brand accent color (`--primary`), medium weight, no underline until hover.

Links inside the footer use `--sidebar-primary` instead.

## Status badges

Base class: `.badge`. Pill-shaped (fully rounded), 12px, SemiBold, uppercase, letter spacing 0.05em, padding 0.25rem 0.75rem, width fits content.

## Layout and containers

| Class | Purpose |
| --- | --- |
| `.section-container` | Centered content block, max width 1200px, padding 5rem 2rem |
| `.section-raised` | Raised section background (`--muted`) for alternating bands |
| `.grid-layout` | Responsive grid, columns at least 250px wide, gap 2rem, top margin 2rem |
| `.card` | Content block with `--card` background, 1px border, `--radius` corners, 1.5rem padding |
| `.chart-box` | Simulated chart container, 180px tall, bars align to the bottom |
| `.chart-column` | A bar inside `.chart-box`, full width, 7.5px rounded top corners |

Page structure: a section wraps a `.section-container`. For an alternating band, put `.section-raised` on the section and keep the container inside it.

Base page styles: the body uses `--background` and `--foreground`, no margin or padding, line height 1.5.

## Header and footer

| Element | Style |
| --- | --- |
| `header` | Flex row, space between, centered vertically, padding 1.5rem 2rem, bottom border, `--background` |
| `footer` | `--sidebar` background, `--sidebar-foreground` text, top border (`--sidebar-border`), padding 4rem 2rem |

- The header shows the site name only. It has no navigation.
- Navigation links go in the footer only.

## Using Tailwind utilities

Tailwind generates only the utilities it finds in the HTML. Any utility works as soon as it appears in a page's HTML and the CSS is rebuilt. Colors use the names in the palette tables, for example `bg-primary`, `bg-success`, `text-muted-foreground`, and `border-border`.

## Adding a new page

1. Create `pages/<name>/index.html` with `assets/styles/<name>.css` and `assets/script/<name>.js` beside it. The File Structure check requires both folders.
2. Link `../../assets/styles/output.css` in the head.
3. Use the standard header and footer.
4. Build with the shared classes above. Page-only styles go in the page's own CSS file.
5. Run `npm run css:build` and `npm run format:check` before opening a pull request.
