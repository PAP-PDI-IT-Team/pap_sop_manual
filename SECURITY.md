# Security

## Reporting a concern

Do not disclose vulnerabilities, credentials, personal information, or confidential operational details in public issues or pull requests.

Use an existing approved private channel to contact the assigned IT mentor or IT team security contact. A project-specific reporting address and response targets have not yet been assigned. Maintainers must establish that channel before broader rollout.

Include the affected page or file, a description, sanitized reproduction steps, and potential impact. Do not attempt to access data or systems outside your authorization.

## Project handling rules

- Keep passwords, tokens, environment files, personal data, and production configuration out of the repository and site.
- Use sanitized examples in procedures, screenshots, issues, and pull requests.
- Obtain IT review before adding external scripts, dependencies, forms, or data collection.
- If sensitive material is exposed, stop sharing it and notify the IT team privately. Credential owners should revoke or rotate exposed credentials through their approved process; deleting a file alone does not remove repository history.

## Support status

The project is an initial scaffold with no formal supported release or security response schedule yet. Hosting and access controls require IT review before internal material is published. A static site does not provide authentication by itself.
