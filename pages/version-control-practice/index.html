Branch flow

flowchart TD
    DEV[Dev branch] -->|Branch off| FIX[Fix branch]
    FIX -->|PR and merge back| DEV
    DEV -->|Deployment| STAGING[Staging site]
    STAGING -->|Issues found| FIX
    BASE[Main branch] -->|Branch off| PRE[Pre-release branch]
    STAGING -->|Pass: manually copy selected lines from dev| PRE
    PRE -->|PR| PB[Preprod branch]
    PB -->|Deployment| PP[Preprod site]
    PP -->|ASD acceptance| MAINPR[PR to main]
    MAINPR -->|Authorized approval and senior merge| BASE[Main branch]
    BASE -->|Automatic deployment| LIVE[Live site]

Working with changes

Stage What happens
Development Branch from Dev [17] to implement the fix. Open a PR back to dev; after merge, test on the staging site deployed from dev. Issues return to the fix branch and through another PR to dev.
Change selection Create a pre-release [20] branch from main. Manually copy/edit the selected, staging-tested code lines from dev into it.
Preproduction A PR [14] proposes those changes for preprod [19].
Production After ASD [6] acceptance, a PR targets main. An authorized person approves, a senior merges, and deployment is automatic.

For QA, huddles, live checks, and closure, see the implementation workflow.

Details to verify

  • Confirm the branch and merge practices for dev, main, pre-release, and preprod before adopting the reported flow.
  • Confirm who may approve a production-targeting pull request and who is responsible for the final merge.
  • Confirm the evidence required for ASD acceptance, production checks, and job-order closure.
